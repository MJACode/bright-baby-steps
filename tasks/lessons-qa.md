# QA agent — lessons library

Append a one-line entry every time the agent misses something or raises a false-positive. Format:

```
- YYYY-MM-DD — <pattern that bit us> — <how to catch it next time>
```

Read this file at the start of every task. Apply what's here.

---

## Open lessons

- 2026-05-15 — `supabase-js` strips `undefined` keys from UPDATE payloads, so `gender: gender || undefined` makes "clear gender" a silent no-op. On every PATCH path, check whether `null` is the intended clear semantics and grep for `|| undefined` in the payload.
- 2026-05-15 — A `catch {}` block in a save mutation hides RLS failures, network errors, and validation errors. Flag every empty catch in any code that talks to Supabase as blocking.
- 2026-05-15 — `column IS NULL` is not automatically an "active session" marker. Before using it that way, confirm the semantic with `SELECT count(*) FROM <table> WHERE <col> IS NULL` on real prod data.
- 2026-05-16 — A PR description claiming a DB-level dedupe trigger that isn't actually in the migration file is a high-risk gap because the app-level dedupe (last-N-rows) silently weakens as row counts grow. Always cross-check trigger/index claims against the migration SQL — and against the live schema via information_schema/pg_trigger when MCP is available.
- 2026-05-16 — Fire-and-forget Supabase builder calls inside an edge function (`.then(...)` with no await, no `EdgeRuntime.waitUntil`) can silently drop on the Edge runtime if the parent fn returns before the underlying request completes. For any side-effect that must land (analytics stamps, last_referenced_at, etc.), require either `await` or `EdgeRuntime.waitUntil(...)`.
- 2026-05-24 — When a new notification path reuses an existing `type` string (e.g. `appointment_reminder` from both `children.next_appointment` and a new `scheduled_visits` block), check whether the legacy block updates `recentTypes` after pushing — if it doesn't, the two blocks can both fire in the same tick for users on both surfaces. Always grep for `recentTypes.add` next to every push that shares a type with the new block.
- 2026-05-24 — Edge functions that build HTML email bodies must HTML-escape user-entered fields (child name, doctor name, location). Without escaping, a parent-entered `<a href="evil">` renders as a real link in their own email — low blast radius but still XSS-shaped. Look for backtick-interpolation of payload fields directly into `<html>` blocks.
- 2026-05-24 — Two queries that read the same underlying table from different components but with non-overlapping query-key suffixes (e.g. `["scheduled-visits", childId]` vs `["scheduled-visits", "next", childId]`) means invalidating one prefix does NOT refetch the other (react-query prefix-match is positional). When a mutation in component A must refresh a derived view in component B, either align the keys or call `invalidateQueries({ queryKey: ["scheduled-visits"] })` (bare prefix). Always grep for every `queryKey: ["<table-name>"` across `src/` when a new mutation lands.
- 2026-05-24 — The `["scheduled-visits", childId]` vs `["scheduled-visits", "next", childId]` prefix-key mismatch reappeared in a second PR despite already being in this file. Bake the check into the first review pass on any new feature that has both a "list" view and a "next/summary" view of the same table — grep `queryKey:.*<name>` across the diff AND the rest of src/ before signing off.
- 2026-05-28 — OAuth auth-code consume was a read-then-write TOCTOU (SELECT consumed_at, then later UPDATE) — double-redeemable under concurrency. On any one-time-token consume, demand an atomic guarded UPDATE (`... WHERE id=$1 AND consumed_at IS NULL`) checked by row-count BEFORE issuing the artifact, never a separate check-then-set.
- 2026-05-28 — Backend-only diffs can still trip the legal-review-log requirement: a feature that opens a NEW child-data egress/disclosure path (e.g. piping child data to a customer's own external AI client) needs a docs/legal-review-log.md entry even with zero frontend/Privacy-page text change. On any new data-export/integration/subprocessor surface, check the log regardless of which files changed.
- 2026-06-06 — A react-query "toggle item in array" mutation that reads the whole array from `query.data` and upserts the rewritten array is a lost-update race: two quick check-offs both read the same stale array and the second clobbers the first. For set/array membership toggles backed by Postgres, demand an atomic array op (`array_append`/`array_remove` via RPC) or at minimum an optimistic-update + refetch, never read-render-state-then-upsert-whole-array.
- 2026-06-06 — A derived card's own today-logs query (`["sleep-today-logs", child, date]`) is NOT refreshed by the shared `["sleep-logs"]` invalidation in useActiveSleep — different key root. When a new card reads the same table under a fresh key, grep every `invalidateQueries` for the writing hook and confirm the new key is covered (or rely on refetchInterval deliberately, and say so).
- 2026-06-06 — An in-progress ("active") item that satisfies the "first actionable" predicate silently consumes the single `minutesUntil`/highlight slot meant for the next upcoming action. When a countdown is "only on the first actionable item", confirm whether active/in-progress should be excluded from that pick.
- 2026-06-19 — A feed that "writes the same status the source page reads" must use the SAME row-identity column the source uses. `parent_financial_checklist.checklist_item_id` is a UUID FK to `financial_checklist_items.id`; the AgePromptBanner `fin-prompt-*` strings are localStorage dismiss keys, NOT item ids — using them for the read-miss-silently and the INSERT FK-violates. On any new write-back into an existing table, grep the existing reader for how it keys the row and confirm the FK target/type matches before trusting "no divergence".
- 2026-06-24 — Skill/key validation via the `in` operator on an object literal passes inherited keys ("constructor","toString","hasOwnProperty"), turning a should-be-400 into garbage indexed downstream. On any `key in OBJECT` allow-list guard, demand `Object.prototype.hasOwnProperty.call(OBJECT, key)` (or `Object.keys().includes`).
- 2026-07-05 — usePreferences keeps per-hook-instance useState with no cross-instance sync: a write from CustomizeHomeSheet's instance never reaches Dashboard/QuickNavGrid's instance until remount, so "toggle → see it on home" flows silently do nothing live (shipped in #156, extended by quick-tiles). On any localStorage-backed hook, check whether writer and reader components share ONE hook instance (props/context) before signing off a toggle feature.
- 2026-07-28 — An RLS-blocked UPDATE/DELETE returns 0 rows with NO PostgrestError, so a `42501` → friendly-copy mapping never fires on those verbs and the success toast lies; meanwhile an INSERT whose policy is `auth.uid() = parent_id OR partner_can_write(parent_id)` is never blocked at all when the client stamps `parent_id = user.id`. Before accepting "RLS protects this", split the check by verb: INSERT (self-stamped parent_id = always allowed), UPDATE/DELETE (silently 0-row). Demand `.select()` + row-count assertion on writes whose success toast matters.
- 2026-08-08 — Deleting a "redundant" FAB without checking that a secondary role/branch (DashboardLayout's `role === "caregiver"` early return to `CaregiverHome`) had NO other logging entry point turned an intended de-dup into a total feature removal for that user segment. Before removing any always-mounted global widget, grep every branch that renders it (not just the two call sites in the PR description) and check each surrounding route/branch for alternate entry points before signing off.
- 2026-08-25 — Never run `git stash` (or any state-mutating git command) to get a lint/build baseline — the parent Claude may commit concurrently and the stash ref can be lost. Get a baseline with `git stash create` + `git diff`, or `git show HEAD:path > /tmp/...` and lint the copy. Read-only means read-only for git too.
- 2026-08-25 — `!activeSide` is NOT the same gate as "no session in flight": a PAUSED timer row still has `active_side = null` while `duration_minutes IS NULL`. Any "add a past entry" trigger gated on `!activeSide` shows up mid-session, and if the parent form saves by UPDATE-ing the bound active row, the manual entry silently overwrites the paused session. Gate on the active ROW (`!active` / `!activeIsBreast`), never on the active SIDE.
- 2026-08-25 — A shared sheet/dialog that collects an optional field (notes) but whose consumer's `onSave` destructures only some of the payload silently discards user-typed content. On any new shared form component, diff the payload type against every consumer's destructure and demand either wiring or a prop that hides the field.
- 2026-08-25 — A timer face that can show something OTHER than the live row (an applied past entry) while its tap handler still reads/writes that live row is a divergence bug: NursingTimer's `toggleSide` kept `activeIsBreast` as the branch condition after the display moved to `showsLiveRow`, so tapping a side paused a partner's running session with zero visible feedback. When a display expression gains a new source of truth, grep every handler in the file for the OLD condition and confirm each one moved to the new one.
- 2026-08-25 — HEAD can move mid-review (the parent Claude committed the working tree while I was building a pre-fix baseline), silently turning `git show HEAD:<file>` into the POST-fix file and making "these tests fail pre-fix" look false. Capture the SHA under review with `git rev-parse HEAD` in the first tool call and diff against that SHA, never the moving `HEAD` ref.
- 2026-08-25 — Verifying "these tests fail pre-fix" without touching the working tree: `git show <pinned-sha>:<path> > <scratchpad>/Old.tsx`, write a throwaway vitest config in the scratchpad that aliases the exact import specifier to that copy (exact-match alias BEFORE the `@/` alias, `root` pinned to the repo, and symlink the repo's node_modules into the scratchpad so `vitest/config` resolves). Run the NEW test file against the OLD component. No stash, no checkout, no writes to the project tree.
- 2026-08-25 — A "seed once per bound row id" ref guard is only as good as the paths that clear it: FeedingLog cleared `boundStartRowId` in the `null` unbind branch, so any tab round-trip that unbinds and re-binds the SAME row (bottle→breast→bottle, breast→bottle→breast) re-armed the seed and silently reverted the parent's typed correction. When a diff adds an once-per-id memo ref, enumerate every writer of the ref AND every sibling component that can push `null` through the same callback (NursingTimer's `onActiveRowChange?.(liveRow)` on remount) — test the round-trip, not just the single bind.
- 2026-08-25 — A controlled Radix Dialog's own "Cancel" button that calls `setOpen(false)` directly NEVER fires `onOpenChange`, so the `if (!open) resetForm()` cleanup in the Dialog's handler is skipped — any sticky ref (`startTouched`, `editingId`, `activeRow`) survives into the next open and, combined with an auto-open effect, gets written to a different row. When a diff adds a ref that guards a saved value, enumerate the dialog's CLOSE paths (Radix onOpenChange / Cancel / programmatic setOpen / navigation exits) and confirm each clears it — the writers/readers enumeration alone is not enough.
- 2026-08-25 — Prove "this ref regressed" by mutation, not by reading: alias the baseline component (`git show <sha>:<path>` → scratchpad) in a scratchpad vitest config and run the SAME repro against baseline and working tree. Baseline-passes + tree-fails is the only statement worth blocking on. Same rig, mutated one line of the tree component, answers "is the new behaviour actually covered by a test?".
- 2026-08-25 — Never `cp` a baseline copy into `src/` for a lint/eslint baseline — `src/` IS writable and the stray file shows up in `git status` for the parent to commit. Use `npx eslint --stdin --stdin-filename <real/path>` and pipe the baseline in.
- 2026-08-25 — An authorship flag (`startTouched`) is scoped to a VALUE but the write it guards is scoped to a ROW: FeedingLog kept the parent's typed start when a *different*, newly-arriving live row bound underneath the open dialog, so Save back-dated a watch/partner session to a time chosen for a separate entry. Whenever a "user-authored, don't re-seed" flag guards a field that is later written to a bound row, demand the flag also record WHICH row it was authored against (`seededRowId`) and re-seed on any other id — and prove it with a bind-after-typing repro, since the same-row round-trip tests all pass either way.
- 2026-08-25 — My own lesson-44 prescription (`seededRowId` anchored at BIND time) was wrong and I asserted it from a scratchpad repro that only checked `logged_at === row.start`, never that the parent's entry survived as an INSERT. Measured: it still fails the crux (re-seeds the picker to the row's start, then UPDATEs the row) and it opens a four-tap stale-claim hijack because it is never cleared on unbind. Anchor an authorship flag at AUTHORSHIP time (`{ forRowId: boundRowId.current }`) and refuse the BIND on mismatch, not just the re-seed. When I prescribe a fix, build it as a variant and run the reviewer's own assertion against it before recommending — a prescription I have not executed is a hypothesis, not a finding.
- 2026-08-25 — A new query key root invented for a NEW view of an existing table (`["sleep_logs-history", …]` next to `["sleep-logs", …]`) is only covered by the writers that call `invalidateAfterLogWrite`; the hook-local `invalidate()` closures in useActiveSleep/useActiveFeed and the inline list in AIChatWidget still invalidate `["sleep-logs"]` only, so timer start/stop/discard leaves the new list stale. Prefer NESTING the new key under the existing root (`["sleep-logs","history",childId,days]`) so every existing prefix invalidation covers it for free; prefix-invalidation never widens the other query's own fetch, so "the page query must not be widened" is not a reason to fork the root.
- 2026-08-25 — `.gitignore` line `logs` (from the stock Node template) silently swallows any new directory named `src/components/logs/`, so a new component builds and type-checks locally but never appears in `git status` and would ship as a missing module. On any diff that adds a NEW directory, cross-check `git status` against `find`/`ls` and run `git check-ignore -v <path>` before signing off.
- 2026-08-25 — `placeholderData: (previous) => previous` in a hook whose query key contains `childId` keeps the PREVIOUS child's rows on screen (with `isPending === false`, so no skeleton) for the whole refetch after a child switch. When keepPreviousData is added for a pagination knob, demand it be scoped: `placeholderData: (prev, prevQuery) => prevQuery?.queryKey[1] === childId ? prev : undefined`.
- 2026-08-25 — A fixed-step "Show earlier days" (+14d) paired with a boolean `hasEarlier` existence probe is a dead button whenever the gap to the next-oldest row exceeds one step: same rows, no new group, no focus move, no announcement. Demand the probe return the older row's DATE and the widening jump to it, not a constant increment.
- 2026-08-29 — A repo-wide RLS pivot (`20260820000000_child_pivot_log_rls.sql`) hardened 17 log tables onto `can_access_child(child_id)` but silently left `speech_journal` on the legacy `parent_id` pivot; a later feature that pipes that table into a shared surface (the pediatrician PDF) inherits the directional `has_partner_access` bug — partner-authored rows are invisible to the child's owner. Whenever a diff adds a NEW read of an EXISTING table into a shared/aggregate surface, diff that table's policy against the scope list of the most recent RLS-hardening migration before signing off; "RLS exists" is not "RLS matches its siblings".
- 2026-08-29 — A COUNT presented next to a clinical benchmark must be a count of the right thing: `select("*", {count:"exact"})` on a table with no unique constraint counts ROWS, and `count ?? 0` conflates "query failed" with "zero", so one failed head-query prints "all time: 0" beside "this period: 5". On any new count rendered into a user-facing artifact, check (a) row-count vs distinct-value semantics against the label, and (b) that null (error) is distinguishable from 0.
- 2026-09-04 — Widening a threshold to kill false positives silently creates a NEW muted state for inputs that used to escalate: raising 3-6mo `longNightGapHours` 8h→14h fixed the normal night but left a 4mo who last fed at 13:00 showing a muted "Overnight: 14h since the last feed". Never review a state machine only at the scenarios the implementer measured — alias the prior commit's module into a scratchpad vite-node config and diff the state/pill/tone/cues signature minute-by-minute across the whole window for every age bracket; the regressions live between the sampled points.
