## Open lessons

- 2026-05-07 — `current_setting('app.*')` for cron / edge secrets silently fails on hosted Supabase because ALTER DATABASE isn't granted to the SQL editor role — use `vault.decrypted_secrets` instead. See migration `20260507050000_cron_jobs_use_vault.sql`.
- 2026-05-07 — Adding a new records-table that references `parent_id` requires adding it to the `delete_user_account()` RPC purge order, otherwise final profiles delete hits an FK violation. Canonical list in `20260507010000_audit_delete_user_account.sql`.
- 2026-05-15 — `feeding_logs` and `sleep_logs` use partial unique indexes on `(child_id) WHERE duration_minutes IS NULL` / `WHERE ended_at IS NULL` to enforce one-active-session-per-child. Any new "active row" pattern should follow the same convention rather than locking at the application layer.
- 2026-05-15 — Always verify a migration is applied to prod via `list_migrations` + a column SELECT — being in `supabase/migrations/` is not the same as being applied. The `is_expected` column was in `schema_migrations` but missing on the live table (likely from a failed or partial earlier apply), so every `AddChildDialog` UPDATE silently 400'd. Spot-check column presence with `information_schema.columns` before assuming a migration is live.
- 2026-05-16 — Subagent sessions don't always get the Supabase MCP tools (`mcp__ac9b166b__*`) wired in even when the parent does — `.mcp.json` may be empty and `supabase` CLI absent. Check available tools / `.mcp.json` early; if missing, write all SQL/edge-function files, document the exact MCP calls the parent must run (`apply_migration`, `deploy_edge_function`, `generate_typescript_types`, `get_advisors`), and report rather than guess at applied state.
- 2026-05-16 — Inline-rebuilding an edge function's bundled file payload from memory rather than reading from disk dropped real content (truncated personas.ts prompts) and introduced a reference error (`{ role: "user", content }` instead of `content: context` in weekly-insights). For any deploy that bundles multi-file source, READ each file from disk and pass the verbatim content — or delegate the deploy to a subagent that does the read+json.dumps and calls `deploy_edge_function` itself. Never paraphrase source in a deploy payload.
- 2026-05-16 — Fire-and-forget Supabase builder calls inside an edge function (e.g. a `.then(...)` UPDATE for `last_referenced_at`) can silently drop on the Edge runtime when the parent fn returns before the underlying HTTP request completes. For any side-effect that must land, wrap in `EdgeRuntime.waitUntil(promise)` (with a fallback `await` when `EdgeRuntime` is undefined for local Deno).
- 2026-05-16 — When in-memory dedupe relies on "last N rows", scale eats the heuristic alive — past row N, duplicate rows can be re-inserted forever. Pair every app-level dedupe with a DB-level `BEFORE INSERT` trigger (`SECURITY DEFINER`, immutable `search_path`) that returns `NULL` to silently skip the dup. See `20260516010000_child_memories_dedupe_trigger.sql`.
- 2026-05-17 — SSE preambles (custom named events like `event: routed`) must be written to the TransformStream writer BEFORE the proxy loop starts pumping Anthropic tokens — otherwise the first OpenAI-shaped `data:` frame races ahead of the named event and frontends parsing the first chunk for routing metadata miss it. See `supabase/functions/chat/index.ts` (preamble write inside the async IIFE, immediately after entering the try block).
- 2026-05-17 — When adding a second Anthropic fetch in an existing edge function (e.g. a classifier + the existing answer call), copy the `anthropic-beta: prompt-caching-2024-07-31` header AND give the classifier's tiny system prompt its own `cache_control: ephemeral` block — otherwise the cheap auxiliary call quietly defeats prompt caching on every request and the per-message cost balloons.
- 2026-05-19 — Inline column CHECK constraints (`col text CHECK (col IN (...))`) get auto-named by Postgres as `<table>_<column>_check`. When widening such a constraint, DROP it by that exact name (idempotent with IF EXISTS) and re-ADD with an explicit name like `<table>_<column>_v2_check` so future migrations can target it deterministically. Prior art: `20260517000000_widen_feeding_logs_check_constraints.sql`, `20260519010000_child_memories_allow_sleep_triage_source.sql`.
- 2026-05-24 — When a new `parent_id`-referencing table arrives after the 2026-05-09 `_purge_user_data()` refactor, DON'T copy the older 2026-05-07 pattern of redefining `delete_user_account()` inline in the new migration. The canonical helper is `_purge_user_data(_uid)`; `parent_id ON DELETE CASCADE` from `auth.users` covers the new table transitively via the final `DELETE FROM auth.users` in that helper. Redefining `delete_user_account()` standalone now would silently revert to a stale purge order that omits `subscriptions`, `rights_requests`, `parent_financial_checklist`, and the new Storage-API path. Document the cascade chain in the migration comment instead.
- 2026-05-24 — Internal edge-function-to-edge-function calls (cron → send-X) need to support BOTH service-role JWT and user JWT callers. Don't gate purely on `auth.getUser()` — a service-role JWT resolves to no user and the function 401s. Instead, decode the JWT's `role` claim (`service_role` vs `authenticated`) and branch: service-role bypasses the recipient-match check (trust the upstream caller's row-level validation); user JWT requires recipient == authenticated email. See `send-visit-reminder-email/index.ts`.
- 2026-05-24 — When adding a new notification type that another block already gates on via a `recentTypes` Set, the new block must `recentTypes.add(type)` immediately after `notifications.push(...)`. Forgetting the add() means the legacy block's push can co-fire with the new block in the same cron tick. Audit every block in `check-notifications/index.ts` that pushes a given `type` and confirm each adds to the dedupe Set.
- 2026-05-24 — Never stamp `*_sent_at` columns BEFORE the upstream side-effect (Resend send, push fan-out, etc.) returns ok. The stamp is the retry signal; setting it before the await means a transient vendor failure permanently swallows the message. Pattern: send first, capture `resp.ok`, stamp only on success. To preserve "no double-fire per tick" without using the stamp, track a local `dispatched` boolean per row.
- 2026-05-24 — Any user-controlled string interpolated into an HTML email body (or any HTML) MUST go through an escape helper. `${child_name}` with `<a href="...">tap me</a>` becomes a real link in Gmail/Apple Mail. Add an `escapeHtml(s)` helper at the top of every send-*-email function and wrap every user-controlled `${...}` in the HTML branch. Plain-text branches don't need it. Values that come from a clamped enum lookup or `Intl.*` formatters are safe and can stay raw — comment why when you skip them.
- 2026-05-24 — When extending an edge function that already has per-message dedupe ("recent 3h notifications"), DON'T tighten the existing query to only fetch the 3h window — the new types need 30 min / 90 min / 24h dedupe scopes. Pull the widest needed window (24h) once and compute per-type `lastSentAt` from the result. Keeps DB reads constant and lets each new type pick its own dedupe interval without re-querying.
- 2026-05-24 — Subagent sessions for backend work continue to lack `mcp__ac9b166b-*` tools (`.mcp.json` is empty). Write the migration / edge function to disk, manually patch `src/integrations/supabase/types.ts` with the new shape so the frontend doesn't immediately fail typecheck, and document the exact MCP calls the parent must run (`apply_migration`, `list_tables`, `execute_sql` for the trigger test, `generate_typescript_types`, `get_advisors`, `deploy_edge_function`).
- 2026-06-04 — Subagent backend sessions STILL lack `mcp__ac9b166b__*` tools (the harness lists them but every call returns "No such tool available") AND have no `supabase` CLI / DATABASE_URL env — so prod writes and live type-regen are impossible from the subagent. Do all read/local work, hand-patch `src/integrations/supabase/types.ts` from the migration SQL so the frontend typechecks (drops the missing-table tsc cascade), prove it with tsc, and hand the parent the exact MCP calls to run: `apply_migration` x2, `list_tables`, `generate_typescript_types` (which replaces the hand-patch).
- 2026-06-04 — When a missing-table tsc cascade is cleared (hand-patching types), previously-masked unrelated errors surface — e.g. `SleepPage.tsx` `Cannot find name 'getErrorMessage'` (missing import from `src/lib/handleRlsError.ts`) and `PumpingSchedule.tsx` `.from("..." as any)` defeating the row-type cast. Report these as separate pre-existing frontend bugs; don't silently absorb them into the "expected remaining errors" count.
- 2026-06-19 — Never seed tax/financial figures (CTC, FSA, HSA, IRA limits) into checklist rows or persona prompts without a YEAR STAMP and a source ref — OBBBA 2025 raised CTC $2,000→$2,200 and DCFSA $5,000→$7,500 (2026), and unstamped "$2,000"/"$5,000" strings silently went stale. Refresh via a NEW idempotent UPDATE migration matched by `title` (never edit the applied original); explicitly comment which figures are intentionally flat year-over-year (gift exclusion, kiddie tax, 529 superfunding). See `20260619000000_refresh_tax_year_figures.sql`.
- 2026-05-24 — When replicating client-side detection logic on the server (e.g. `detectOffPlan` for `bedtime_drift`), the comparison direction matters — `Math.abs(avg) > 30` fires for BOTH early and late drift, mislabeling early-bedtime nights as "drifting later". Mirror the client's signed comparison exactly (`avg > 30` when `avg` already encodes `start - target` minutes). Any server/client off-plan logic divergence is a correctness bug, not just a style nit.
- 2026-07-02 — An eligibility window exactly as wide as the cron interval (3h cron, [07:00,10:00) local gate for daily_briefing) gives each recipient ONE tick per day — any downstream suppressor (quiet hours, daily cap) that eats that tick makes the feature permanently undeliverable, silently. Size the window to guarantee a retry tick (>= 2x cron interval) AND pre-check suppressing conditions at eligibility time so a suppressed attempt isn't "spent". Compose every filter layer against the cron cadence before declaring a time-windowed feature done.
- 2026-07-02 — A "never dropped" contract (appointment_reminder) must hold on EVERY suppression path — mutes, quiet hours, AND cap; exempting two of three meant a user-set `muted_categories: ["appointments"]` silently killed cues whose `reminder_*_sent_at` stamp was already written (lost forever, no retry). Enforce such exemptions in ONE place as early as possible (strip the category at prefs-parse in resolvePrefs) instead of remembering them per-filter.
- 2026-07-05 — `deno check` on edge functions is impossible in subagent sessions: `deno.land` and `esm.sh` CONNECTs are 403'd by the egress proxy policy (confirmed via `$HTTPS_PROXY/__agentproxy/status`), so remote imports never resolve. Substitute: `npx tsc --ignoreConfig --noEmit --strict` on _shared modules with no remote imports (full check), and `--noResolve --skipLibCheck` on index.ts files (syntax + local-identifier check; filter expected TS2307/TS2304-Deno/TS7006 noise).
- 2026-07-05 — QA rejected a ~170-line `buildChildContextBlock` helper shipped with ZERO consumers ("Phase 2 will use it") — YAGNI applies to _shared modules too: ship a helper only alongside its first real consumer. Same pass: two serial awaits for independent DB loads on chat's pre-first-token path (use `Promise.all`), and an access-probe SELECT + profile SELECT hitting the same table twice (one `loadChildCore` call can serve as both probe and data source). Audit every new await chain for parallelism and every new query for an existing fetch it can piggyback on.
- 2026-07-17 — Adding a new value to a one-row-per-user enum column (subscriptions.tier gained 'pro') silently REVOKES the old value's features anywhere gates check exact equality — granting 'pro' to the test account killed every `tier === "plus"` consumer gate (usePremium + 4 edge functions). When widening a tier/status enum, grep ALL exact-equality checks on that column and decide superset semantics explicitly before shipping the migration.
- 2026-07-17 — A denormalized owner column (`slp_id` copied onto child tables for cheap RLS) is forgeable without a composite FK: `(client_id, slp_id) references parent(id, slp_id)` (backed by a `unique (id, slp_id)` on the parent) makes cross-owner pairing impossible at the DB level. Plain single-column FKs let an attacker pair another owner's parent row with their own slp_id and pass RLS.
- 2026-07-17 — Non-streaming Anthropic edge functions that parse model JSON must check `stop_reason === "max_tokens"` before JSON.parse — truncated output otherwise surfaces as a misleading 422 "model returned non-JSON" instead of a distinct 502 (e.g. `generation_truncated`). Applies to generate-speech-class-style siblings too.
