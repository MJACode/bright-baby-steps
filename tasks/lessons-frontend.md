# Frontend agent — lessons library

Append a one-line entry every time the agent gets corrected. Format:

```
- YYYY-MM-DD — <what bit us> — <how to avoid it next time>
```

Read this file at the start of every task. Apply what's here.

---

## Open lessons

- 2026-05-15 — Never put a state setter's source-of-truth (`dialogOpen`) in a `useEffect` dep array that also calls the setter unconditionally — infinite loop.
- 2026-05-16 — `activeChild` from `useChildren()` gets a new object reference on every react-query refetch. Effects that depend on `[activeChild]` and call `resetForm()` will wipe in-progress user edits when the refetch fires. Gate one-shot init effects with a `useRef(false)` sentinel.
- 2026-05-16 — react-query v5 removed the `onSuccess`/`onError`/`onSettled` callbacks from `useQuery` (still on `useMutation`). Any code passing them is silently ignored — sync derived state via a `useEffect` keyed on the query data's id instead.
- 2026-05-16 — Every Supabase write mutation needs an `onError` toast. Missing `onError` = silent failure = "I clicked save and nothing happened" bug.
- 2026-05-16 — Form button labels and DB CHECK constraint values must match exactly. `AddChildDialog` shipped with buttons mapped to `["boy", "girl", "other"]` while the `children.gender` CHECK accepts `('male'|'female'|'other'|'prefer_not_to_say')`. Two of three options always failed. **Before adding any field that writes to a constrained column, query the constraint and align values — use a `{ value, label }` map so display copy and stored value are decoupled.**
- 2026-05-16 — Validation that rejects a save can read to users as "save is broken." `DiapersPage` blocks the edit save when changing a wet log → dirty if color/consistency aren't filled in (correct logic, hostile UX). When the underlying data is missing required follow-ups, either pre-fill sensible defaults at the moment the user changes type, or surface the requirement inline next to the changed field — not via a generic destructive toast.
- 2026-05-16 — A pulse / `animate-ping` pseudo-element scales to 2x its parent. Without `pointer-events-none`, the expanded pseudo blocks clicks on siblings rendered below it in a flex column. Any `::before/::after` with `animate-ping` MUST include `before:pointer-events-none`.
- 2026-05-16 — **Meta-lesson (parent-Claude).** Speculative root-causing from code-reading alone produces fixes that look right but don't address the actual bug. For any "X is broken" report: (a) ask the user for the literal error toast / console error text before diagnosing, (b) query the database schema for any column the failing path touches, (c) reproduce the click path through the actual component file to confirm the failing branch — don't trust a sub-agent's diagnosis without checking against the real evidence.
- 2026-05-20 — Module-level event buses (`onChatOpen`/`openChat`) only fire if their subscriber is mounted. When a FAB widget is mounted inside a page-level `<Outlet />` component instead of the layout, every sub-route renders without the subscription and `openChat()` calls silently no-op. Mount global-bus subscribers in `DashboardLayout` (or a layout-level provider), never in a single `Dashboard.tsx`-style page.
- 2026-05-24 — When picking up a partially-written component from a prior session, always read the actual file first and reconcile the service signature with the call site before editing the service. A new PDF builder with `(visit, child, reminders)` shape can't be called by a component that already passes `{ visitId, childId, parentId }` — pick one shape and refactor both ends together in one pass.
- 2026-05-24 — React Query keys match positionally. Put the entity id (childId) at a stable index across every queryKey that touches the same table, and put discriminators (`"next"`, `"recent"`, etc.) at the end. Otherwise a sibling mutation invalidating `["scheduled-visits", childId]` won't prefix-match `["scheduled-visits", "next", childId]` and the consumer stays stale.
- 2026-05-24 — A `useQuery` consumer that renders an empty-state when `data` is undefined will flash "nothing here" during the loading window. Always destructure `isLoading` and branch `isLoading ? <skeleton/loading> : empty ? <empty> : <list>` — three states, not two.
- 2026-05-24 — Plan-stated "unused" types are not always unused. `MethodFlavor` in `sleepTriage.ts` was tagged as unused in a plan but is actually referenced by `TRIAGE_CONTENT`, `lookupContent`, `useSleepTriage`, and `sleepPlan.ts`. Always `grep -rn <Type>` before deleting/renaming a "currently unused" type — it may be load-bearing for a content table the plan didn't survey.
- 2026-05-24 — `useMutation.isPending` flips false **before** the consuming `useQuery` refetches with the inserted row. Guarding a "fire-once on empty list" effect with `list.length === 0 && !mutation.isPending` has a window-of-vulnerability that can double-insert. Use a `useRef<string|null>` sentinel keyed on the parent record id (reset in an effect when the id changes) instead of `isPending`.
- 2026-05-24 — When advancing through a sequence of inserts, derive the next index from the **just-completed row** (`completedRow.interval_index + 1`), not from `max(items) + 1` computed off the render-captured array. Rapid double-taps during the optimistic gap will compute the same max twice and duplicate-insert. Also gate the action button on every relevant `isPending` flag.
- 2026-05-24 — Terminal-state UI: when a stepper hits its terminal stage, **hide** the forward-advance button entirely, don't just `disabled` it. A greyed-out "Advance to 6" on stage 5 misleads users into thinking a stage 6 exists.
- 2026-05-25 — shadcn form-field primitives shipped with hard-coded text-sm (14px), which triggers iOS Safari's auto-zoom-and-trap on focus — every text input/textarea/select must render at 16px+ on mobile. Use text-base md:text-sm to match the Input primitive's pattern.
- 2026-05-30 — The native Capacitor SpeechRecognition path must explicitly call onResult(finalTranscript) in the `listeningState 'stopped'` handler — the web branch gets this for free via `recognition.onend`, so it's easy to forget. Also attach `partialResults`/`listeningState` listeners BEFORE `await SpeechRecognition.start()` (late attach drops early partials) and bracket each session with `removeAllListeners()` (before re-adding and after firing onResult) to stop listener stacking across sessions.
- 2026-06-06 — Read-modify-write of an array column (`completed_items = [...current, id]`) from cached `useQuery` data is a lost-update race across devices. Use an atomic server-side RPC to toggle one element, and for a sibling write (wake_anchor) OMIT the array from the upsert payload so it isn't clobbered — on conflict only the named columns hit the SET clause, the array keeps its existing/default value.
- 2026-06-06 — A consumer query key `["sleep-today-logs", childId, today]` is NOT prefix-matched by an invalidate that only hits `["sleep-logs","active",childId]`. When a mutation lives in one hook (`useActiveSleep`) but a different hook owns a derived day-logs query, pass an explicit `onSuccess` at the `.mutate(...)` call site that invalidates the consumer's exact key — don't assume the mutation's own invalidate covers it.
- 2026-06-06 — Date-key consts that must roll over at midnight (`format(new Date(),"yyyy-MM-dd")`) must be plain consts recomputed each render, never `useState`/`useMemo([])`, so an existing 60s tick re-derives them. The query key must use that same value.
- 2026-06-06 — `source='timer'` scoping must be applied in the pure engine too, not just the active-session query. A null `ended_at` only means "in progress" for timer rows; voice/manual logs legitimately carry null end times, so an engine branch keyed on `!ended_at` alone shows a phantom active session. (e.g. `WatchBridge.tsx` component + `watchBridge.ts` util). They're distinct on case-sensitive Linux (so `npm run build`, CI, and Vercel all pass) but collide on case-insensitive macOS (HFS+/APFS) — the Codemagic mac builder resolved `import …/WatchBridge` to the `.ts` util, which didn't export the component, failing "Build web assets". Give modules distinct stems (`watchBridgeClient.ts`). The bug is invisible on every Linux check, so audit for case-only filename pairs whenever adding a PascalCase component next to a camelCase util in the same folder.
- 2026-06-10 — `npm run build` is vite-only and does NOT type-check — shipped a hard TS2322 (prop passed to a component that never declared it) with a green build. Always run `npx tsc --noEmit -p tsconfig.app.json` before declaring done, in addition to `npm run build`.
- 2026-06-19 — A localStorage *dismiss key* string (`fin-prompt-0-3`) is NOT the DB row identity. `parent_financial_checklist.checklist_item_id` is a UUID FK → `financial_checklist_items.id`; keying read-suppression OR write-back on the banner-dismiss string meant the feed never matched FinancialTab's rows (always re-showed) and every ✓/snooze FK-violated. When a feed mirrors another tab's checklist, resolve to the SAME id that tab writes (query the items table by exact seeded title → uuid) and key both read and write on it. Also: don't invent new `status` values (`snoozed`/`not_applicable`) for a table whose CHECK constraint you can't verify and whose only writer uses `completed`/`not_started` — route snooze/dismiss to a localStorage transient instead, and keep ✓ writing exactly `completed`.
- 2026-07-01 — A "consume-on-use" ref carrying intent from event A to event B (chat-open `source` → conversation creation) is only correct if EVERY path that breaks the A→B chain also clears it. Health-skill handoffs prefill without sending, and sourced sends into a restored existing convo never consume — the stale ref then stamped later unrelated conversations. Enumerate all exits between A and B (dialog close, "New chat" reset, entry points that bypass the event bus like voice mode) and null the ref in each.
- 2026-07-01 — Third occurrence of the incomplete-invalidation pattern (see 2026-05-24 positional-keys and 2026-06-06 sibling-hook lessons): a new writer to the log tables (voice fast-path) shipped its own hand-picked invalidation list and missed derived keys ("streak", "analytics-month", "last-logged", "rhythm-*", "next-event", "day/week-events") that an existing writer (QuickLogFAB) already covered. Never write a per-call-site invalidation list for a shared table — ONE canonical list lives in `src/lib/logInvalidation.ts` (`invalidateAfterLogWrite`); every writer to feeding/sleep/diaper/milestone/temperature logs must use it, and every new derived query on those tables must add its key root there.
- 2026-07-02 — Settings hooks that resolve defaults from query `data` make a query ERROR indistinguishable from "user has defaults": isLoading flips false, prefs resolve to pure defaults, controls re-enable, and the first toggle writes defaults+patch over the user's real saved values. Gate consumers on `isReady: query.isSuccess` (not !isLoading) AND guard the save function itself with the same flag.
- 2026-07-01 — Fixed silent-error handling only on the mutations I edited (add) while my new UI reused untouched ones (delete/toggle) with the same gap — when new UI wires onto an existing mutation, that mutation's error path is in scope; apply `if (error) throw` + `onError` toast to every mutation the new surface invokes.
- 2026-07-04 — A `role="button"` container with an Enter/Space `onKeyDown` swallows keyboard activation of nested interactive children: their keydown bubbles up and the container's `e.preventDefault()` cancels the native button's Enter/Space click (mouse works, keyboard silently doesn't). Every keyboard handler on a card/row that wraps inner buttons MUST start with `if (e.target !== e.currentTarget) return;`.
- 2026-07-05 — Tailwind palette literals (`bg-amber-50`, `text-red-900`, `text-orange-600`) evade the `#hex` grep but still break brand tokens AND dark mode. Grep diffs for `(amber|orange|red|green|slate|gray)-\d{2,3}` too; express severity tiers as opacity steps on semantic tokens (`warning/5 → warning/10+solid warning badge → destructive`) so tiering survives theme flips.
- 2026-07-05 — Progress percentages must use a denominator scoped to what the user could plausibly have achieved (age-appropriate set = current + earlier groups), not the full catalog — and the numerator must be filtered to the same id set or early-achieved future items can push it past 100%. A catalog-wide denominator makes an on-track user read as failing forever.
- 2026-07-05 — `src/integrations/supabase/types.ts` is stale for `profiles` (`has_partner`, `primary_interest` missing). tsc's excess-property check only fires on a `.update()` literal whose keys are ALL unknown — mixed literals (one known column present, e.g. `updated_at`) slip through, so existing writes compile while a new lone-column write fails. Flag types regeneration to backend; meanwhile include a real known column (`updated_at: new Date().toISOString()`) rather than casting. **SUPERSEDED same day: types were regenerated and `has_partner`/`primary_interest` are known columns — the ride-along workaround was removed. Grep types.ts before assuming staleness; remove such workarounds (and their comments) as soon as types regen lands.**
- 2026-07-05 — An `await supabase...update()` whose result is never destructured is a silent failure — supabase-js doesn't throw on error, it returns `{ error }`. The onboarding-completion profiles UPDATE shipped this way and failed silently in prod for weeks. Every awaited Supabase write must destructure `{ error }` and surface it; and when the write follows an already-committed INSERT, handle the error NON-fatally (toast + continue) — throwing would retry the whole path and duplicate the earlier insert.
- 2026-07-28 — Role-gating half the write controls is the same as gating none. When a table's INSERT policy is `auth.uid() = parent_id OR partner_can_write(parent_id)` and the client stamps `parent_id: user.id`, the first disjunct is always true, so RLS never evaluates the role clause — the UI gate is the ONLY thing stopping a viewer. Derive one `canWrite` const and wrap EVERY add/edit/delete affordance (including row-level edit buttons — render a plain `<div>` for read-only, not a disabled button), and never comment such a gate as "UX guardrail, not a security boundary" without first checking whether the policy actually excludes the role.
- 2026-07-28 — `useCurrentRole` returns `data ?? "owner"`, so a viewer optimistically reads as owner for the first render pass; gating writes on the value alone flashes controls that fire an RLS-rejected UPDATE. Expose/consume the query's `isSuccess` (`useCurrentRoleQuery`) and require it before showing any write control — don't change the hook's permissive default, other consumers depend on it.
- 2026-07-28 — Toasting `err.message` from a Supabase failure leaks raw Postgres text ("new row violates row-level security policy for table ..."). Map known codes (42501 = insufficient_privilege) to a sentence that says what happened and what to do next; keep `err.message` only for genuinely unexpected errors.
- 2026-07-28 — A brand-new Collapsible section that ships without `defaultOpen` while its siblings set it is invisible on arrival. Match the surrounding sections' default-open state when adding a feature to an existing accordion-style page, and toast the side effects of a delete (`ON DELETE SET NULL` relocating child rows) so users aren't surprised by rows moving.
- 2026-07-28 — A `canWrite` gate on the JSX alone is not enough: a Sheet already open when the role flips mid-session still fires the mutation. Put the guard in the `mutationFn` too. It matters differently per verb — for INSERT the client gate is the ONLY enforcement (own-uid `parent_id` satisfies the policy), and for UPDATE/DELETE an RLS-blocked write returns **0 rows with no error**, so the 42501 branch never fires and the user gets a false success toast. Throw the same user-facing copy the error-describer returns so `onError` renders one consistent sentence.
- 2026-07-31 — `query.isSuccess` is not a latch: in react-query v5 a failed BACKGROUND refetch flips `status` to `"error"` while `data` is retained, so an `isResolved`-style gate goes false for a user who was already resolved (offline owner told "you're view-only"). Gating writes on `isSuccess` is right, but the unresolved branch must have its OWN copy ("still checking your access") — never share the denied-permission message between "not settled yet" and "you lack permission".
- 2026-07-31 — Changing only a search param is a SAME-ROUTE navigation: the page component stays mounted, so an uncontrolled `<Tabs defaultValue={paramTab}>` ignores it and a `?tab=` deeplink silently no-ops whenever the user is already on that page. Any tab/accordion whose state is deeplinked must be controlled off `useSearchParams` with `onValueChange` writing back (`{ replace: true }` so tab taps don't stack history entries).
- 2026-07-05 — `usePreferences` (localStorage + per-instance useState) has NO cross-instance sync: `setPrefs` in one component never re-renders another component's hook instance, so a writer (CustomizeHomeSheet) and a live reader (QuickNavGrid) silently disagree until remount. When one surface writes a pref another surface renders live, lift ONE hook instance into the common ancestor and pass `prefs`/`setPrefs` down as props.
- 2026-08-08 — Deleting a global FAB without checking every mount site loses a role's ONLY write affordance. `QuickLogFAB` was CaregiverHome's sole logging entry point (DashboardLayout short-circuits caregiver role to `<CaregiverHome/>` for every route, so caregivers never reach SleepPage/DiapersPage/FeedingPage's inline quick-log UI). Before removing a floating/global component, grep every import site and check whether any of them is the *only* path to a capability for some role — don't assume "it's just UI chrome." Fixed by reusing `VoiceQuickLogButton`/`VoiceQuickLog` (already generic across feeding/sleep/diaper/temperature/milestone and already stamps `parent_id: auth uid` the same way manual per-tab forms do, so it needs no extra role gating) rather than inventing a new dialog.
- 2026-08-25 — A seeded default that the validator then rejects is a dead control: `useSessionAnchor` seeded `startAt = now − defaultDurationMin` and froze it, so every duration chip longer than the default derived a future end and disabled Save (3 of 6 nap presets dead on arrival). When a default value and a validation rule are derived from the same quantity, check EVERY reachable input against the rule, not just the seeded one — and distinguish an app-authored placeholder (tracks) from a user-authored value (sticks) with a `touched` flag.
- 2026-08-25 — A one-way anchor is only half a fix: freezing the start after an *end* edit doesn't preserve the end (end is derived from start+duration), so the dead-duration-chip bug just moved one interaction deeper. When two of three quantities are canonical and the third is derived, model which one the user authored as an explicit `"none" | "start" | "end"` mode and re-derive the *other* canonical value from their assertion — then table-test every input value against every mode.
- 2026-08-25 — Gating a UI affordance on a *derived* sub-state (`activeSide`) instead of the *row* (`activeIsBreast`/`activeIsPump`) reopens a write path the parent already bound: `activeSide` is null for a paused session too, so "Add past feed" reappeared while the parent form still held the paused row as `activeRow` and the save UPDATEd (destroyed) it. Gate on the same condition the row-binding effect uses, not on a narrower slice of it.
- 2026-08-25 — A handler that writes a value into state the *display expression doesn't read* is a silent no-op: NursingTimer's past-feed apply set `editLeft/editRight` while the face read `editMode ? editX : activeIsBreast ? server : 0`, so a 30-minute feed rendered `00:00` and the next remount's `onDurationChange(0)` wiped it. When adding a second producer for a displayed value, re-derive the display expression from *all* producers — don't just add a setter.
- 2026-08-25 — Never latch an anchor/mode off a value the validator will reject. `setEndAt` took `anchor="end"` even for an end in the future (`maxDate` gates the calendar, not the hour/minute wheels), so every duration chip then derived an equally-future start and no control could recover. Guard the latch on the value being valid; keep updating the derived quantity so the error still points at the field the parent actually touched.
- 2026-08-25 — Clearing state from inside a handler (`onActiveRowChange?.(null)`) does not stick when an effect re-derives that same state on the next refetch. The guard has to live in the effect's condition (a `pastApplied` flag), not only at the call site — otherwise a window-focus refetch silently re-binds the row and Save overwrites a partner's live session.
- 2026-08-25 — `type="number"` + `min={0}` blocks the steppers but not typing `-5`. Clamp in the change handler (`Math.max(0, Number(v) || 0)`), and put the clamp in a pure exported helper so it's testable and can't drift back into an inline expression.
- 2026-08-25 — Two conditions describing the same fact ("is a live row in play?") always drift: the display moved to `showsLiveRow` while `toggleSide` kept `activeIsBreast`, so a tap paused a partner's session the face wasn't showing. Derive ONE value — the row itself (`liveRow = ownedByThisForm ? active : null`) — and make the face, the ticker, every handler and the parent binding read only that; keep a second predicate only where it means something genuinely different, and name it for that meaning (`breastRowExists`).
- 2026-08-25 — Never `git stash` to get a lint/build baseline: the parent Claude can commit the working tree concurrently and the stash pop can collide. Use `git show <sha>:<path> > <scratchpad copy>` and lint/test the copy instead.
- 2026-08-25 — A "seed once per row id" ref (`boundStartRowId`) that clears itself on unbind protects nothing: every unbind→rebind of the SAME row re-seeds and overwrites the correction the parent typed (watch-bottle → Breast → Bottle; NursingTimer pushes null on mount). When the value being protected is user-authored, model **authorship** (`startTouched` ref set only by the picker/openEdit, cleared by resetForm and by app-authored pushes) not binding identity — one flag, no per-id bookkeeping, and it also closes the Reset-restamps-now hole.
- 2026-08-25 — A parent effect that unbinds on `feedType` change commits AFTER the child's mount effect, so a blanket `handleActiveRowChange(null)` on "not bottle" would clobber the breast row NursingTimer had just bound. Scope such an effect to the types the parent actually owns (`feedType === "breast"` → return) whenever a child component binds the same state.
- 2026-08-25 — Unbinding a row does NOT undo the state it seeded: clearing `activeRow` on leaving bottle still left `loggedAt` at that session's start, so the solid INSERT landed hours ago. When you remove a binding, also revert every field that binding wrote (guarded by the touched flag).
- 2026-08-25 — Never state "N of M tests fail against baseline" from reasoning. Run them: `git show <sha>:<path>` into a scratchpad copy, swap it in, run, restore in the SAME bash invocation. Reported 2 of 4 when it was 3 of 4 (one failed at its precondition, not its advertised assertion) and the wrong figure reached a PR description.
- 2026-08-25 — One callback carrying two authorships is the same bug in a new door: `onStartAtChange` clamped `startTouched=false` for all three NursingTimer pushes, but one of them (past-feed apply) is the value the parent just chose — a later feed-type switch then re-stamped it to now. Split the prop by authorship (`onTimerStartAt` app-authored / `onPastStartApplied` parent-authored) so the type carries the distinction, and route EVERY write of the guarded value through one of two named setters so a fourth call site can't pick the wrong one.
- 2026-08-25 — A controlled Radix `Dialog` only calls `onOpenChange` for closes *it* initiates: a Cancel button wired to `setDialogOpen(false)` skips the `!open` reset entirely, so `startTouched`/`editingId`/`activeRow` all survived into the next open and a later auto-opened live row got UPDATEd with the cancelled dialog's `logged_at`. Converge every close on ONE `closeDialog()` (`setDialogOpen(false)` + reset + unbind) and grep for stray `setDialogOpen(false)` call sites — a reset that lives only in `onOpenChange` protects only the paths Radix owns.
- 2026-08-25 — Don't arm a persistence flag on a path that can't benefit from it: `openEdit` used `setAuthoredStart` although edit mode already blocks every re-seeder (`editingId` guard + `editMode` guard), so merely *opening* a log and cancelling armed `startTouched` with zero typing. Use the app-authored setter wherever the guard is already structural — the cheapest way to arm a flag is the likeliest way to leak it.
- 2026-08-25 — "N of M fail against baseline" must name WHICH baseline. Reported 1 of 7 measured against the un-fixed working tree when the reviewer-reproducible figure was 3 of 7 against the pinned SHA. Always run the suite against `git show <sha>:<path>` copies AND state the SHA in the figure; a regression introduced by your own diff will *pass* at the pinned SHA, so report that separately rather than folding it into one number.
- 2026-08-25 — An authorship flag needs the *identity of what it was authored against*, captured at authorship time. `startTouched` alone let an unrelated arriving session become the row Save UPDATEs (back-dated to the parent's manual time, their entry discarded); anchoring the id at *bind/seed* time instead (a sticky `seededRowId`) still mis-keeps a value authored during an unbound window. Model it as one ref carrying both facts — `authoredStart: { forRowId: string | null } | null`, `forRowId` read from a synchronous mirror of the bound row — and let a mismatch refuse the binding, not just the re-seed, so the form still INSERTs the feed the parent was typing.
