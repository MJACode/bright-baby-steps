# Frontend agent — lessons library

Append a one-line entry every time the agent gets corrected. Format:

```
- YYYY-MM-DD — <what bit us> — <how to avoid it next time>
```

Read this file at the start of every task. Apply what's here.

---

## Open lessons

- 2026-05-15 — Never put a state setter's source-of-truth (`dialogOpen`) in a `useEffect` dep array that also calls the setter unconditionally — infinite loop.
- 2026-05-16 — `activeChild` from `useChildren()` gets a new object reference on every react-query refetch. Effects that depend on `[activeChild]` and call `resetForm()` will wipe in-progress user edits when the refetch fires. Gate one-shot init effects with a `useRef(false)` sentinel.
- 2026-05-16 — react-query v5 removed the `onSuccess`/`onError`/`onSettled` callbacks from `useQuery` (still on `useMutation`). Any code passing them is silently ignored — sync derived state via a `useEffect` keyed on the query data's id instead.
- 2026-05-16 — Every Supabase write mutation needs an `onError` toast. Missing `onError` = silent failure = "I clicked save and nothing happened" bug.
- 2026-05-16 — Form button labels and DB CHECK constraint values must match exactly. `AddChildDialog` shipped with buttons mapped to `["boy", "girl", "other"]` while the `children.gender` CHECK accepts `('male'|'female'|'other'|'prefer_not_to_say')`. Two of three options always failed. **Before adding any field that writes to a constrained column, query the constraint and align values — use a `{ value, label }` map so display copy and stored value are decoupled.**
- 2026-05-16 — Validation that rejects a save can read to users as "save is broken." `DiapersPage` blocks the edit save when changing a wet log → dirty if color/consistency aren't filled in (correct logic, hostile UX). When the underlying data is missing required follow-ups, either pre-fill sensible defaults at the moment the user changes type, or surface the requirement inline next to the changed field — not via a generic destructive toast.
- 2026-05-16 — A pulse / `animate-ping` pseudo-element scales to 2x its parent. Without `pointer-events-none`, the expanded pseudo blocks clicks on siblings rendered below it in a flex column. Any `::before/::after` with `animate-ping` MUST include `before:pointer-events-none`.
- 2026-05-16 — **Meta-lesson (parent-Claude).** Speculative root-causing from code-reading alone produces fixes that look right but don't address the actual bug. For any "X is broken" report: (a) ask the user for the literal error toast / console error text before diagnosing, (b) query the database schema for any column the failing path touches, (c) reproduce the click path through the actual component file to confirm the failing branch — don't trust a sub-agent's diagnosis without checking against the real evidence.
- 2026-05-20 — Module-level event buses (`onChatOpen`/`openChat`) only fire if their subscriber is mounted. When a FAB widget is mounted inside a page-level `<Outlet />` component instead of the layout, every sub-route renders without the subscription and `openChat()` calls silently no-op. Mount global-bus subscribers in `DashboardLayout` (or a layout-level provider), never in a single `Dashboard.tsx`-style page.
- 2026-05-24 — When picking up a partially-written component from a prior session, always read the actual file first and reconcile the service signature with the call site before editing the service. A new PDF builder with `(visit, child, reminders)` shape can't be called by a component that already passes `{ visitId, childId, parentId }` — pick one shape and refactor both ends together in one pass.
- 2026-05-24 — React Query keys match positionally. Put the entity id (childId) at a stable index across every queryKey that touches the same table, and put discriminators (`"next"`, `"recent"`, etc.) at the end. Otherwise a sibling mutation invalidating `["scheduled-visits", childId]` won't prefix-match `["scheduled-visits", "next", childId]` and the consumer stays stale.
- 2026-05-24 — A `useQuery` consumer that renders an empty-state when `data` is undefined will flash "nothing here" during the loading window. Always destructure `isLoading` and branch `isLoading ? <skeleton/loading> : empty ? <empty> : <list>` — three states, not two.
- 2026-05-24 — Plan-stated "unused" types are not always unused. `MethodFlavor` in `sleepTriage.ts` was tagged as unused in a plan but is actually referenced by `TRIAGE_CONTENT`, `lookupContent`, `useSleepTriage`, and `sleepPlan.ts`. Always `grep -rn <Type>` before deleting/renaming a "currently unused" type — it may be load-bearing for a content table the plan didn't survey.
- 2026-05-24 — `useMutation.isPending` flips false **before** the consuming `useQuery` refetches with the inserted row. Guarding a "fire-once on empty list" effect with `list.length === 0 && !mutation.isPending` has a window-of-vulnerability that can double-insert. Use a `useRef<string|null>` sentinel keyed on the parent record id (reset in an effect when the id changes) instead of `isPending`.
- 2026-05-24 — When advancing through a sequence of inserts, derive the next index from the **just-completed row** (`completedRow.interval_index + 1`), not from `max(items) + 1` computed off the render-captured array. Rapid double-taps during the optimistic gap will compute the same max twice and duplicate-insert. Also gate the action button on every relevant `isPending` flag.
- 2026-05-24 — Terminal-state UI: when a stepper hits its terminal stage, **hide** the forward-advance button entirely, don't just `disabled` it. A greyed-out "Advance to 6" on stage 5 misleads users into thinking a stage 6 exists.
- 2026-05-25 — shadcn form-field primitives shipped with hard-coded text-sm (14px), which triggers iOS Safari's auto-zoom-and-trap on focus — every text input/textarea/select must render at 16px+ on mobile. Use text-base md:text-sm to match the Input primitive's pattern.
- 2026-05-30 — The native Capacitor SpeechRecognition path must explicitly call onResult(finalTranscript) in the `listeningState 'stopped'` handler — the web branch gets this for free via `recognition.onend`, so it's easy to forget. Also attach `partialResults`/`listeningState` listeners BEFORE `await SpeechRecognition.start()` (late attach drops early partials) and bracket each session with `removeAllListeners()` (before re-adding and after firing onResult) to stop listener stacking across sessions.
- 2026-06-06 — Read-modify-write of an array column (`completed_items = [...current, id]`) from cached `useQuery` data is a lost-update race across devices. Use an atomic server-side RPC to toggle one element, and for a sibling write (wake_anchor) OMIT the array from the upsert payload so it isn't clobbered — on conflict only the named columns hit the SET clause, the array keeps its existing/default value.
- 2026-06-06 — A consumer query key `["sleep-today-logs", childId, today]` is NOT prefix-matched by an invalidate that only hits `["sleep-logs","active",childId]`. When a mutation lives in one hook (`useActiveSleep`) but a different hook owns a derived day-logs query, pass an explicit `onSuccess` at the `.mutate(...)` call site that invalidates the consumer's exact key — don't assume the mutation's own invalidate covers it.
- 2026-06-06 — Date-key consts that must roll over at midnight (`format(new Date(),"yyyy-MM-dd")`) must be plain consts recomputed each render, never `useState`/`useMemo([])`, so an existing 60s tick re-derives them. The query key must use that same value.
- 2026-06-06 — `source='timer'` scoping must be applied in the pure engine too, not just the active-session query. A null `ended_at` only means "in progress" for timer rows; voice/manual logs legitimately carry null end times, so an engine branch keyed on `!ended_at` alone shows a phantom active session. (e.g. `WatchBridge.tsx` component + `watchBridge.ts` util). They're distinct on case-sensitive Linux (so `npm run build`, CI, and Vercel all pass) but collide on case-insensitive macOS (HFS+/APFS) — the Codemagic mac builder resolved `import …/WatchBridge` to the `.ts` util, which didn't export the component, failing "Build web assets". Give modules distinct stems (`watchBridgeClient.ts`). The bug is invisible on every Linux check, so audit for case-only filename pairs whenever adding a PascalCase component next to a camelCase util in the same folder.
- 2026-06-10 — `npm run build` is vite-only and does NOT type-check — shipped a hard TS2322 (prop passed to a component that never declared it) with a green build. Always run `npx tsc --noEmit -p tsconfig.app.json` before declaring done, in addition to `npm run build`.
- 2026-06-19 — A localStorage *dismiss key* string (`fin-prompt-0-3`) is NOT the DB row identity. `parent_financial_checklist.checklist_item_id` is a UUID FK → `financial_checklist_items.id`; keying read-suppression OR write-back on the banner-dismiss string meant the feed never matched FinancialTab's rows (always re-showed) and every ✓/snooze FK-violated. When a feed mirrors another tab's checklist, resolve to the SAME id that tab writes (query the items table by exact seeded title → uuid) and key both read and write on it. Also: don't invent new `status` values (`snoozed`/`not_applicable`) for a table whose CHECK constraint you can't verify and whose only writer uses `completed`/`not_started` — route snooze/dismiss to a localStorage transient instead, and keep ✓ writing exactly `completed`.
- 2026-07-01 — A "consume-on-use" ref carrying intent from event A to event B (chat-open `source` → conversation creation) is only correct if EVERY path that breaks the A→B chain also clears it. Health-skill handoffs prefill without sending, and sourced sends into a restored existing convo never consume — the stale ref then stamped later unrelated conversations. Enumerate all exits between A and B (dialog close, "New chat" reset, entry points that bypass the event bus like voice mode) and null the ref in each.
- 2026-07-01 — Third occurrence of the incomplete-invalidation pattern (see 2026-05-24 positional-keys and 2026-06-06 sibling-hook lessons): a new writer to the log tables (voice fast-path) shipped its own hand-picked invalidation list and missed derived keys ("streak", "analytics-month", "last-logged", "rhythm-*", "next-event", "day/week-events") that an existing writer (QuickLogFAB) already covered. Never write a per-call-site invalidation list for a shared table — ONE canonical list lives in `src/lib/logInvalidation.ts` (`invalidateAfterLogWrite`); every writer to feeding/sleep/diaper/milestone/temperature logs must use it, and every new derived query on those tables must add its key root there.
- 2026-07-02 — Settings hooks that resolve defaults from query `data` make a query ERROR indistinguishable from "user has defaults": isLoading flips false, prefs resolve to pure defaults, controls re-enable, and the first toggle writes defaults+patch over the user's real saved values. Gate consumers on `isReady: query.isSuccess` (not !isLoading) AND guard the save function itself with the same flag.
